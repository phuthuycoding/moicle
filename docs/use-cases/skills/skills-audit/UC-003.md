# Use Case

## Overview

| Field | Value |
|---|---|
| ID | UC-003 |
| Name | "clean up" routes to cleanup skill, never feature-build |
| Requirement reference | FR-003 |
| Goal | Auto-invocation is deterministic — each trigger phrase owned by exactly one asset |
| Primary actor | Claude Code (skill auto-invocation) |

## Supporting Actors
- npm end-user

## Preconditions
- FR-003 applied: `feature-build` description no longer claims `clean up` / `improve code`

## Trigger
User types "clean up codebase" (or another phrase audited in FR-003).

## Main Flow

| Step | Actor / system | Action | Outcome |
|---|---|---|---|
| 1 | user | types "clean up codebase" | phrase matches `cleanup` description only |
| 2 | Claude Code | auto-invokes `cleanup` | DEAD-CODE/DUPLICATE workflow runs — never `feature-build` REFACTOR |

## Alternative Flows
### A1
- Trigger: refactor intent phrase used

| Step | Action | Outcome / return to main flow |
|---|---|---|
| A1.1 | user types "refactor" or "migrate to ddd" | matches `feature-build` description → REFACTOR mode; boundary intact |

## Exception Flows
### E1

| Trigger | Handling | Resulting state / message |
|---|---|---|
| Audit finds a phrase in two descriptions | one owner chosen per phrase boundary; loser drops it | zero duplicated phrases shipped |

## Postconditions
- Trigger map is a function: phrase → exactly one skill/command

## Business Rules
- `cleanup` owns dead-code/duplicate vocabulary; `feature-build` owns build/refactor/deprecate vocabulary
- Generic verbs ("improve", "clean up") belong to the narrower skill

## Data
- All `assets/**/SKILL.md` and `assets/commands/*.md` description fields

## Acceptance Criteria
- [ ] Audit script/test finds zero phrases claimed by two assets
- [ ] `feature-build` description lacks `clean up` and `improve code`
