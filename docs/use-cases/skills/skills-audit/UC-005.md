# Use Case

## Overview

| Field | Value |
|---|---|
| ID | UC-005 |
| Name | Upgrade leaves no stale removed assets |
| Requirement reference | FR-007 |
| Goal | Users upgrading moicle have a working, documented path to purge `doc.md`/`feature-track` leftovers |
| Primary actor | npm end-user |

## Supporting Actors
- Claude Code (would otherwise auto-invoke stale skills)

## Preconditions
- User previously installed moicle ≤3.1.0 (has `feature-track` skill dir and `doc.md` command installed)
- User upgrades the package (`npm i -g moicle@latest` / `moicle upgrade`)

## Trigger
User wants a clean state after upgrading.

## Main Flow

| Step | Actor / system | Action | Outcome |
|---|---|---|---|
| 1 | user | upgrades package | new package ships without doc/feature-track assets |
| 2 | user | follows README "stale items" note: `moicle uninstall` then `moicle install` | uninstall removes stale items (it operates on what's installed, not what ships) |
| 3 | system | reinstall writes fresh tree | installed set == shipped set; no stale skill remains invocable |

## Alternative Flows
### A1
- Trigger: user prefers surgical removal

| Step | Action | Outcome / return to main flow |
|---|---|---|
| A1.1 | README documents exact paths (`~/.claude/commands/doc.md`, `~/.claude/skills/feature-track/`) | user deletes the two entries manually |

## Exception Flows
### E1

| Trigger | Handling | Resulting state / message |
|---|---|---|
| `enable`/`disable`/`status` called on a stale installed item | CLI operates on installed files; must not crash | item toggles/listed normally — stale items remain manageable until removed |

## Postconditions
- README documents the stale-cleanup path
- Integration test proves `uninstall` removes a stale item placed in the target tree

## Business Rules
- `install` must NOT delete arbitrary user files — pruning only via documented `uninstall`→`install` cycle or manual removal
- Removed items remain disable-able/enable-able while installed (no crash)

## Data
- Stale paths: `{claude}/commands/doc.md`, `{claude}/skills/feature-track/`
- README upgrade section

## Acceptance Criteria
- [ ] README documents stale-item cleanup (both flows)
- [ ] Integration test: stale item placed in temp install → `moicle uninstall` removes it; `moicle status` on it doesn't crash
